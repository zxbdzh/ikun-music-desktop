# AurioClub 完整移植整改设计

## 目标

依据 Apifox 项目 `8689463` 的 18 个已发布接口和原站交互审计，将 IKUN 播客模块从“基础可用”整改为契约完整、流程完整且符合桌面端可访问性要求的实现。

## 分阶段交付

1. 修正订阅偏好同步契约与账户同步状态；兼容已产生的旧数组快照。
2. 接入热门发现、收藏和播放历史，并提供相应的资料库视图。
3. 实现订阅分组、排序及 OPML 导入导出。
4. 补齐注册、重置/修改密码、用户名和设备关联等账户流程。
5. 完善弹窗焦点管理、异步反馈、下载持久状态和长列表性能。
6. 对照 18 个接口逐项复审，并执行全量测试、类型检查和生产构建。

每个阶段在定向验证通过后独立提交，提交信息使用中文 Conventional Commits。

## 数据与同步设计

`subscriptions_json` 严格序列化为 `SubscriptionSnapshot`：

- `groups`：包含 `id`、`name`、`isExpanded`、`sortOrder`。
- `sources`：包含 `id`、`label`、`type`、`url`、`groupId`、`image`。

第一阶段把现有订阅源归入稳定的默认分组，拉取端同时接受规范对象和历史 ID 数组。第三阶段引入分组持久化后，读写统一使用完整快照，避免编辑订阅时覆盖云端分组。

播放进度、完成状态和收藏状态继续通过 episode state 作为单一事实来源；资料库只做该状态的查询和呈现，不另建重复状态。

## UI/UX 设计

- 同步状态分别呈现“同步中”“已同步”“同步失败”“登录已过期”和“仅保存在本机”。
- 失败状态显示可理解的原因，并提供重试或重新登录路径。
- 所有异步按钮在执行期间禁用并改变文案；失败保留上下文，允许就地重试。
- 模态框打开后聚焦首个有效控件，限制 Tab 焦点，Escape 关闭，关闭后恢复触发按钮焦点。
- 超过 50 项的单集列表采用分页/渐进加载，避免一次创建数百个操作控件。
- 交互控件使用可见文本或明确的辅助名称，状态提示使用适当的 live region。

## 验证

每阶段至少包含对应单元测试，并执行主进程与渲染器 TypeScript 检查。最终阶段执行全部 Vitest、生产构建和 18 接口覆盖复审；只有这些证据全部通过才视为整改完成。
