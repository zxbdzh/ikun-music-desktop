# 播客转写、说话人标注与 BetterLyrics 联动设计

## 目标

IKUN Music 负责播客音频缓存、ASR、简体规范化、说话人分离、AI 身份映射和字幕缓存。BetterLyrics 只消费 IKUN 的逐字稿协议，并随播放时间显示逐行、逐字字幕及说话人前缀。

## 已确认约束

- ASR 生成的中文统一为简体；英文和中英混排保持原样。
- 发布者字幕保持原文，不做繁简转换。
- 本地说话人分离先产生稳定的 `speaker-1`、`speaker-2` 标识。
- AI 只接收节目资料、说话人编号和代表性文本，不上传音频。
- AI 无法可靠判断身份时保留“说话人 1”，不得猜测姓名。
- 用户手工设置的说话人姓名优先级最高，AI 不覆盖。
- Whisper ASR 在 Windows 优先使用 CUDA；说话人分离优先使用 DirectML，两者失败时分别自动回退 CPU。
- 音频缓存、下载目录和模型目录跟随用户自定义播客路径。
- ASR、说话人分离和 AI 标注使用统一任务队列，用户可以中止并继续。

## 架构与数据流

1. IKUN 下载或复用缓存音频，并以 16 kHz 单声道 PCM 供本地处理。
2. ASR 按片段生成句级和逐字时间轴，写入协议 v2 快照。
3. ASR 文本在保存前做简体规范化，字词索引按转换后的文本重建。
4. 说话人分离复用同一音频，输出时间区间到声纹编号的映射，再把 `speakerId` 写回字幕行。
5. AI 根据节目元数据和每位说话人的代表性片段返回严格 JSON 映射；映射只更新 `speakers`，不改变正文和时间轴。
6. 每次正文、时间轴或说话人变化时递增 `revision`，并通过现有 SSE `transcript` 事件发布描述符。
7. BetterLyrics 在发现更高版本后拉取一次增量；播放进度只驱动本地时间轴，不触发网络请求。

## 任务状态

任务阶段包括排队、准备音频、下载模型、ASR、说话人分离、AI 标注、保存、取消中、已中止、完成和失败。状态包含总进度、片段进度、当前执行器、回退原因、心跳、耗时和错误。

中止时终止当前子进程并取消待执行片段，原子保存已经完成的字幕。继续时依据音频指纹、模型版本和已完成片段恢复，不重复处理已有结果。附加阶段失败不得使已有字幕不可用。

## 模型管理

说话人模型首次使用时按需下载到 `<播客缓存>/models/speaker-diarization/<版本>`。下载使用 `.part` 临时文件，展示进度，并在原子替换前校验 SHA-256。设置页展示版本、占用空间、存储位置、执行器和最近错误，并提供下载、校验、删除和打开目录操作。

Windows 默认执行策略为“自动”：ASR 优先 CUDA，说话人分离优先 DirectML，初始化或运行失败时回退 CPU，并向状态 UI 分别报告实际执行器和原因。CUDA 版安装包自带所需 CUDA 12 运行库；标准安装包可复用本机 CUDA 12.x。当前 sherpa-onnx 预编译包没有 DirectML provider，因此说话人分离会明确使用 CPU，不能仅凭系统存在 `DirectML.dll` 宣称 GPU 已启用。

## AI 身份映射

设置项包括启用开关、OpenAI 兼容 Base URL、模型名称、API Key 和测试连接。API Key 使用 Electron `safeStorage` 加密后仅保存在本机，不写日志、不云同步。

请求使用固定 system 指令和结构化 JSON 输入；节目字幕被视为不可信数据，不能改变指令。响应必须通过本地 schema 校验。身份优先使用明确姓名，其次为“主持人”或“嘉宾”，无法确定则保留编号名称。

## 协议兼容

保留 `/status`、`/transcript`、`/transcription-status`、`/transcription-control` 和现有 SSE 地址。协议 v2 新字段均为可选，旧客户端可忽略。字幕行保留 `speakerId`，`speakers` 提供名称和来源。

BetterLyrics 同一时刻最多执行一个字幕请求；请求期间到达的新版本合并为下一轮。内容切换或断开 IKUN 时取消旧请求并清空旧内容，旧响应不得覆盖新节目。

## 验收

- ASR 中文为简体，英文和中英混排不被破坏，发布者字幕保持原文。
- IKUN 可见模型下载、转写、分离、AI 标注、实际执行器和错误状态。
- GPU 失败时 CPU 回退成功；任务可中止、继续且保留已生成部分。
- 已识别身份显示为 `姓名：正文`，未知身份显示为 `说话人 1：正文`。
- IKUN 与 BetterLyrics 均按真实逐字时间戳高亮。
- BetterLyrics 连续接收播放进度时仍能稳定拉取字幕，不发生请求饥饿。
- 切换节目、断线重连、应用重启和转写中增量更新均能恢复正确字幕。
- 普通音乐歌词、LX 接入和花再音响功能不回归。

## 实现顺序

1. 修复 BetterLyrics 字幕请求合并与播放进度解耦。
2. 在 IKUN ASR 输出边界增加简体规范化并补回归测试。
3. 扩展任务、协议和 UI 状态，保留现有中止/继续能力。
4. 接入本地说话人分离模型及 DirectML/CPU 回退。
5. 接入 OpenAI 兼容身份映射、安全存储和手动操作。
6. 联调两个应用，完成构建、运行和安装包验证。
